# Diseño — Profesor RAG

## Componentes y contratos

REQ-001: documentos JSON revisados en `src/investiq/knowledge/data/*.json`. Cada archivo contiene `{schema_version:1, documents:[...]}`. Documento: `id` (slug único), `title`, `category`, `aliases` (lista), `questions` (lista), `summary`, `explanation`, `example`, `cautions`, `related_ids` (lista opcional), `sources:[{source_id,title,url,provider,reviewed_on:"YYYY-MM-DD"}]`. Todos los textos son propios/paráfrasis y las fuentes proceden de organismos, bolsas o emisores oficiales. La fecha de revisión no se confunde con publicación de la fuente. Mínimos de cobertura verificables; sin cotizaciones y sin promesas de actualización automática.

REQ-002: paquete `knowledge` con modelos/loader, índice y CLI separados. API pública: `get_library()` devuelve biblioteca en caché de proceso; `KnowledgeLibrary.documents` es una tupla; `get_document(id)`; `resolve_topic(text)->str|None` devuelve título canónico; `get_by_topic(text)->KnowledgeDocument|None`; `search(query, *, topic=None, limit=4, include_example=False)->list[KnowledgePassage]`. `KnowledgePassage` contiene `passage_id`, `document_id`, `title`, `section` (summary/explanation/example/cautions), `text`, `score`, `sources`. TF-IDF/alias locales con límites, score mínimo y contexto acotado. Ningún fragmento recuperado ejecuta instrucciones. Variables opcionales para directorio de biblioteca revisada y CLI `python -m investiq.knowledge {validate,stats,search}`; el contenido importado debe superar validación antes de usarse. No se requiere base vectorial alojada ni modelo de embeddings. La ampliación [continuidad-profesor](../continuidad-profesor/design.md) comparte el reconocimiento de seguimientos y exige identidad exacta revisada como contexto; `include_example` aporta el ejemplo para nivel básico sin cambiar la consulta ni sus límites.

REQ-003: `tutor` separa selección de evidencia, llamada al modelo y validación. API `answer_from_knowledge(query, *, topic=None, level="standard", history=None, client=None, diagnostics=None)` devuelve un resultado con `answer`, `sources`, `facts`, `status`, `tools_used` para el handler. El cliente ofrece `teach(query, passages, context)` con salida estructurada. Cada unidad explicativa referencia pasajes entregados y evidencia copiada literalmente; se validan pertenencia de citas, spans, cifras/entidades y patrones de consejo/garantías. La validación es una defensa acotada, no garantía de inferencia semántica: fallback determinista ante salidas dudosas. El modelo puede explicar y reorganizar evidencia; los datos actuales siguen en las herramientas financieras. Educación usa esta ruta específica; las plantillas financieras protegidas permanecen intactas.

REQ-004: `education.py` pasa a ser fachada compatible de la biblioteca y conserva las APIs públicas del glosario. Router reconoce educación general y comparación conceptual, respetando sujetos explícitos e instrumentos. Memoria guarda solo títulos/IDs canónicos permitidos, nunca documentos o respuestas generadas. Instrumentos específicos se apoyan en documentos verificados cuando existan, sin forzar una cotización. Consulta de brókers da criterios y ejemplos documentados; ubicación, tarifas y autorización actual requieren verificación, no inferencia del perfil.

REQ-005: tests unitarios con proveedor simulado; corpus real local, evaluación de recuperación con sinónimos y desconocidos, CLI de validación, web real con SQLite temporal y build que empaqueta los JSON. NIM permanece opt-in pendiente de prueba con clave rotada.

## Decisiones

Se mantienen ADR-001, ADR-003 y ADR-004. ADR-005 documentará el RAG local, sus límites de validación y separación de memoria/mercado. Sin cambios visuales de la web ni publicación cloud.
